# 双尺度序列网络与设备自适应

研究页选择「因果卷积 + 双尺度 GRU + 注意力」，对应 `architecture=gru`。网络直接读取按时间排列的OHLCV序列，不先把整个窗口压成少量统计量交给MLP。

## 网络

共60,548个参数，两个输出：h分钟上涨概率与收盘收益，h可选1/5/15。

- 短支路：最近k根一分钟行情（默认30），7维token → 两层因果卷积（32通道，膨胀率1/2）→ 两层64维GRU → 注意力汇聚。
- 长支路：最近78根**已经结束**的5分钟聚合行情 → 32维GRU → 带有效长度掩码的注意力汇聚。最多约一个完整交易日，允许历史跨日，但不计算隔夜收益。
- 背景与反馈支路：约1/5/20日的6维历史统计，加最近已成熟的预测概率、GT涨跌、预测收益、GT收益、收益误差及可用标记，共12维 → 32维映射。
- 融合后使用64维表示与两个输出头，分类BCE、收益Huber损失。离线学习率3e-4，AdamW、权重衰减0.01，梯度范数裁剪1.0。

7维token包括对数收益、实体/上影范围/下影范围相对开盘的变化、log(1+成交量)、日内时间sin/cos。价格变化乘100；归一化仅用早期训练数据拟合，运行时固定。5分钟聚合以交易时钟对齐，未完成或有缺口的聚合不进入长支路。

GRU隐藏状态在每次完整窗口内计算，在线权重变化后重新编码当前窗口；不把同一段重叠行情重复累计进持续hidden state。跨窗口记忆来自长序列、历史摘要、成熟样本回放与学习权重。

## 训练与在线更新

训练内部按时间约60%/40%划分：早期数据初始化无反馈教师，清除跨分界标签；固定教师为后段生成样本外预测，只有预测目标已成熟时才生成该后段样本的误差反馈，再训练最终网络。教师预测不以未来标签为输入。

历史数据按真实连续段记录；超过50,000候选样本时，在每股原始行情流里创建序列快照**之前**按固定步长抽样，限制内存且保留各股样本。抽样间隔不被误认为行情缺口。所有GT时间仍保持真实h分钟跨度。

运行时每分钟都读取行情并预测。GT在h分钟后成熟，先计分、更新误差输入，再放入最多512条的近期回放缓存。默认每16条成熟样本进行一次权重更新，从缓存按确定间隔选最多16条，包含最新样本；在线学习率3e-5。`adapt=false`关闭权重更新，但仍可读取已成熟反馈。

前2k个运行观察禁入场，内部第k根起预测、第k+h根起得到GT。预先载入历史不消耗适应期。每股独立模型、优化器、待成熟队列和回放；验证与测试分别从同一离线权重开始。跨日/缺口清除短窗口、未成熟标签和误差输入；保留长期背景、已成熟回放与权重。

离线产物不包含在线运行状态。独立checkpoint包含在线权重、AdamW状态、回放、短长历史和待成熟样本。保存时所有权重/优化器张量转到CPU，换机器加载时重建网络并选择设备。

## CUDA与CPU

```sh
uv sync --locked --extra neural --python 3.12
uv run --extra neural uvicorn quant_workbench.api:app --host 127.0.0.1 --port 8000
```

默认 `QUANT_TORCH_DEVICE=auto`，按 CUDA → CPU 选择实际可用后端；MPS支持已放弃，面向CUDA生态开发。可显式指定：

```sh
QUANT_TORCH_DEVICE=cuda uv run --extra neural quant-workbench study ...
QUANT_TORCH_DEVICE=cpu uv run --extra neural quant-workbench study ...
```

指定不可用设备时明确报错，不悄悄切换。模型训练元数据含`training_device`，运行统计含`runtime_device`。CUDA路径启用cudnn自动调优（形状固定）与TF32矩阵精度（Ampere及以后GPU），吞吐更高但与纯FP32数值不逐位一致；`QUANT_TORCH_DEVICE=cpu`保持标量路径。CPU与CUDA数值与耗时可能不同，不能保证逐位一致。

离线训练后用训练段已成熟标签对最终网络logits做温度校准（网格搜索最小化NLL，平局偏向1.0），推理概率按 `sigmoid(logit/T)` 输出；在线更新仍以未缩放logits计算损失。元数据记录`temperature`，旧检查点缺省为1.0。校准只使用开发期数据，不触碰验证/测试段。

PyTorch为可选依赖；基础安装仍能运行旧模型。GRU实验或产物缺少PyTorch时会给出安装提示。普通`uv sync`可能移除未选择的neural extra，因此后续同步与`uv run`都应保留`--extra neural`。模型产物记录PyTorch核心版本，跨设备可加载，同核心版本不同CUDA后缀允许；版本变化需重新训练或匹配原版本。

## 训练与推理加速

GRU 只有约 6 万参数。在线推理逐股、逐分钟执行，每次一个样本；行情校验、特征、交易规则和结果记录在 CPU 上完成，GPU 工作之间存在空隙。低 GPU 利用率不等于没有使用 GPU，应结合完整任务耗时、每秒处理行情数和 `runtime_device` 判断。linear / RBF / MLP 使用 sklearn 的 CPU 路径，GPU 加速开关只影响 GRU。

目前默认启用以下优化，不改变网络、训练 batch=128、epoch 数、在线更新间隔、股票隔离或标签成熟顺序：

- 单样本 CUDA Graph：复用固定形状的 GPU 运算图，减少每根行情重复从 Python 提交小 kernel 的开销。每次仍读取当前输入和最新在线权重，两个预测头合并一次传回 CPU。图与设备缓冲区不保存进模型文件，重载后重新建立；不支持捕获时警告并退回普通推理。
- 离线特征缓存：同一训练阶段的归一化样本和标签驻留 GPU，跨 epoch 复用。默认上限 256 MiB，且不超过当时空闲显存的 20%；超过预算则沿用分批准备。进入反馈阶段后重新生成缓存，不复用尚未更新的反馈。
- CPU 数据准备：离线历史背景使用按股票分组的因果滚动计算，避免每根行情复制最多 7,800 条历史收益；教师反馈循环使用预先提取的行记录，避免逐行构造 pandas Series。

开关在**工作台启动前**配置，已有模型也可使用推理加速：

```sh
# 默认启用 CUDA Graph，训练缓存上限 256 MiB
./scripts/start.sh

# 兼容性排查：关闭图捕获或训练缓存
QUANT_CUDA_GRAPHS=0 QUANT_TRAIN_CACHE_MIB=0 ./scripts/start.sh
```

合成基准不读取、修改真实行情或实验结果：

```sh
# 将编号换成实际空闲 GPU；每组重复三次，排除初次库初始化
CUDA_VISIBLE_DEVICES=7 QUANT_TORCH_DEVICE=cuda uv run --locked --extra neural \
  python scripts/benchmark_sequence.py --sessions 20 --output artifacts/gru-benchmark.json
```

2026-09-18 在空闲 RTX 4090、PyTorch 2.6.0+cu124 上的三次中位数（k=30、h=5、训练5轮、在线每16条成熟样本更新一次）：

| 训练规模 / 在线规模 | 优化前训练 | 优化后训练 | 优化前在线 | 优化后在线 |
| --- | ---: | ---: | ---: | ---: |
| 1,950 / 1,950 根 | 1.43 秒 | 1.49 秒 | 4.60 秒 | 3.02 秒 |
| 7,800 / 1,950 根 | 6.75 秒 | 5.01 秒 | 4.57 秒 | 2.74 秒 |

第二组训练耗时减少约26%，在线耗时减少约40%；两组均产生1,805次预测、111次在线更新。第一组训练未见稳定提升。优化前代码为 `5d0fd2c`，原始重复记录见 [GRU 基准 JSON](benchmarks/gru-2026-09-18.json)。共享主机 CPU 仍可能影响耗时，以上不是所有任务的固定加速承诺。

基准分别记录完整离线训练（包含特征准备、教师反馈、校准）和包含在线更新的逐根推理耗时。结果受 GPU 型号、共享服务器其他任务、股票数和数据规模影响。小数据集的离线训练可能没有可测的整体加速；不能只根据 GPU 利用率百分比评价优化效果。

## 本轮研究协议

SIP范围2025-11-01至2026-02-01：训练至2025-12-16，验证至2026-01-01，2026年1月为新最终测试。每股9候选：三类旧规则；新趋势回调/状态组合各两组持仓风险参数；标准状态组合分别搭配MLP/GRU（k30、h5、离线3轮、成本倍数1.5）。

验证按交易日分前后两半，评分为较差半段收益率−0.25×全段最大回撤，且至少5笔完整交易，评分非正则持币。所有标的选择冻结后再测新月份。旧规则使用同一筛选标准。额外成本×1.5/2场景只作诊断，不看测试收益重新选型。

规则改进与更复杂的网络都需要实际数据验证，不预设其收益一定优于旧方案。收益目标仍为收盘到收盘，实际交易在次分钟成交并由规则退出，模型输出不等于持仓净利润。
