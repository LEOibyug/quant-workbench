# 本地存储预算第一版

日期：2026年9月17日。所有MB/GB/TB均为十进制；系统磁盘显示的GiB为二进制。当前阶段没有下载真实付费行情。估算只用于选数据范围，不代表供应商报价或可保证的文件大小。

## 推荐预留

首版以5只研究股票加SPY、QQQ两个基准、2年常规时段1分钟OHLCV为例，建议为整个项目预留 **10—20 GB**，持续清理无用实验。行情本身约 **33—88 MB**，保守按 **0.1—0.3 GB**保存文件、元数据及分区开销；研发环境、缓存、特征和实验记录是主要占用。

Mac初始化前可用约77 GiB，适合分钟级起步。未来加入逐笔报价时先限定1—2只股票、1—5个交易日测量，不能把两年的完整盘口下载当作分钟线的小幅升级。

## 假设与计算

7个标的 × 2年 × 252日／年 × 390分钟／日 = **1,375,920行**。

这里用每年252个完整交易日做预算，实际以交易日历为准；不含盘前盘后和夜盘。OHLCV记录至少包含UTC时间、标的、开高低收和成交量，压缩格式采用Parquet/Zstandard。

以每行压缩后24—64字节估算，得到33,022,080—88,058,880字节。保留原始标准化数据、加工结果和一份备份共三份时，按最高值计约264 MB；这不是所有模型和特征的总预算。

## 合成数据实测

运行 `uv run python scripts/benchmark_storage.py`，Python3.12.14 / PyArrow23.0.1环境下：

| 项目 | 结果 |
| --- | ---: |
| 合成记录数 | 1,375,920 |
| 按标的及20个模拟交易日分文件 | 182个 |
| Arrow列数据大小 | 76,461,840字节，约76.5 MB |
| Parquet/Zstandard文件总大小 | 26,813,845字节，约26.8 MB |
| 实测压缩后每行 | 19.49字节 |

合成价格四舍五入到美分，随机波动和成交量由固定种子生成；日期是人工连续会话，并非交易所真实日历。其压缩率不等同于真实供应商数据。因此规划范围仍保留24—64字节／行，不直接使用较低的合成结果。测量文件在临时目录生成并自动移除，脚本可复跑；版本和编码变化可能改变文件大小。

## 不同粒度的数量级

以下分钟／秒线仍为7个标的、2年。

| 数据 | 记录数量假设 | 压缩数据估算 | 含三份副本的估算上限 |
| --- | --- | --- | --- |
| 1分钟OHLCV | 138万行 | 0.033—0.088 GB | 0.264 GB |
| 1秒OHLCV，所有秒都保留 | 8256万行 | 1.98—5.28 GB | 15.85 GB |
| 逐笔成交，平均10—100事件／秒／标的 | 8.26亿—82.56亿事件，24—64字节／事件 | 19.8—528 GB | 约1.59 TB |
| 报价更新，平均100—1000事件／秒／标的 | 82.56亿—825.55亿事件，32—80字节／事件 | 264 GB—6.60 TB | 约19.8 TB |

逐笔和报价行是**情景计算**，不是对候选股票实际事件率的测量。指定交易所、全市场覆盖、报价过滤、空秒、数据Schema和时段都会极大改变占用。盘口逐订单数据不能套用OHLCV压缩率。需要先取样，按真实事件率和字节数外推。

例如仅买入2个标的×5个交易日的报价样本，按上述报价情景约0.75—18.72 GB，仍可能超过分钟数据两年总量。

## 整个工程的预算

| 内容 | 初期预留 | 说明 |
| --- | ---: | --- |
| 源码、文档、Git历史 | 0.05—0.2 GB | 排除课件、行情和构建产物 |
| Python虚拟环境、解释器、前端依赖和下载缓存 | 1—3 GB | 缓存可能在项目目录外，不要只看Git大小 |
| 两年分钟行情、元数据和副本 | 0.3—1 GB | 预留额外字段、分区和数据修订 |
| 特征、实验结果、日志和小模型 | 2—5 GB | 需要保留策略；不要每个实验复制全量数据 |
| 下载临时文件、处理峰值和余量 | 3—10 GB | 解压时可能同时保留压缩与解压文件 |
| 建议整体容量 | **10—20 GB** | 超过阈值先清理与归档，再扩大数据范围 |

100个float32特征 × 1,375,920行，仅数值数组就约0.55 GB；20个完全复制的实验约11 GB，尚未算索引和模型。这说明共享数据版本、复用特征、限制缓存比优化几十MB行情更重要。

NVIDIA Linux环境额外安装PyTorch/CUDA相关wheel可先预留5—15 GB，具体以选定版本为准；模型检查点和训练缓存另计。GPU显存、系统内存和磁盘空间是三个独立预算，不能相互替代。此项目基础环境未安装GPU框架。

## 保留策略

- 行情按供应商／市场／粒度／标的／年月分区；保留来源与版本，避免重复下载。
- 实验引用数据快照，保存参数、代码版本和指标，不重复复制全量行情。
- 初期日志按大小轮转，失败实验的临时文件可清理；选中的实验与模型另行保留。
- 用Git保存代码；数据与模型用独立备份。一次本地副本不能防止整块磁盘故障。
- 接入真实数据后记录每标的每日字节数和事件数，以实测替换本估计。
