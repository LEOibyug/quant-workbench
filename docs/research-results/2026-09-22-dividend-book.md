# 普通现金分红账本与LIN身份核查

本轮实现独立研究账本，尚未接入线上页面或原账户回测。它解决分红在应收和可用现金之间的会计转换；不构成新策略，也没有声称修正后收益已提高。

## 权益和现金分开

`scripts/cash_dividend_book.py` 仅接受外部已核验、普通、USD、税前现金分红。调用方必须提供证据引用、除息日、支付日及明确的前收盘整股持仓。构造器的verified只是调用方声明，程序不自动验证来源真假，不能直接给供应商批量记录设置该标记。

除息日开盘前按前收盘持仓确认应收；后续卖出股票不抹掉权益，当日新买入不增加该次权益。支付日在收盘后将应收转为现金，从下一交易日才能动用。周末支付于后续第一交易日收盘转现金，这是保守撮合约定，并非声称真实券商如此入账。支付日可以与除息日相同，但仍不在当日开盘提前花用。

使用Decimal保留金额精度。每次支付只能发生一次；已赚分红始终等于累计支付加未付应收。不同事件ID但相同股票和除息日也先拒绝，要求上游完成身份和事件归并，而非猜测能否相加。特殊分红、foreign、due bill、非USD或税后口径不混入此适配器。

缺失股票持仓不当作零；同一日所有快照通过检查后才创建任何权益，避免处理到一半才报错。禁止跳过除息日，也不静默忽略账本开始之前的除息事件：既有权益需要显式初始化方案，本版本尚未实现开账导入，应由调用方使用与模拟起点相符的事件集。付款跨模拟终点时应收保持存在。

## 数字例子及验证

纯合成例：前收盘10股、股价100、每股派0.24。理论除息价99.76时，股票997.60加应收2.40仍为1000；可用现金没有增加。除息后卖出全部股票，支付日仍收到2.40；下一日再次结算不会重复收到。当日才买10股但前收盘为零，收到的该次分红为零。

2项测试覆盖上述守恒、卖出后权益、除息日买入、重复支付、同日身份歧义、未验证币种/特殊事件拒绝、快照缺失时无部分更新，以及漏过除息日。运行 `uv run --locked pytest -q tests/test_cash_dividend_book.py`，全部通过。完整合成逐日轨迹见dividend-book-evidence.json。

## LIN重组证据

两个尝试的Linde官网公告链接返回404，不视作已读取。取得[2023年年报镜像](https://www.annualreports.com/HostedData/AnnualReportArchive/l/NYSE_LIN_2023.pdf)，定位并目视核验PDF第64页（印刷页56）的会计政策附注：2023-03-01完成内部重组，旧股份按1:1交换新控股公司股份，公司仍称Linde plc并继续使用LIN代码。

该证据支持“同一代码可能对应先后不同证券身份”，因此API两个CUSIP不能简单看成同一持仓同时获得两份股息。但此页没有给出两CUSIP映射或2023-03-13分红记录的替代关系；本轮未武断删除某条，也未自动支付两次。需再核实历史身份及该笔公告。原始PDF和抓取状态哈希、核验范围见dividend-book-evidence.json。

## 接入前剩余工作

批量核验事件币种、税前口径、支付规则和历史身份后，才能接入共享现金账户。接入时不仅要增加最终收益，还需在每日权益/止损/现金预算/逐股贡献中保持一致，并单独处理除息引起的价格基准变化。现有1120条记录不因这个账本通过合成测试就变成全部可用；策略适用性及跨股票池盈利目标仍未完成。
