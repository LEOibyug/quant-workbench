# 普通分红接入研究账户：现金、风险与贡献一致性

完成研究专用的端到端分红接入，尚未使用未核实的1120条供应商记录生成所谓修正收益。线上接口没有传入此研究参数；真实账户、网页和当前已发布策略未切换。工程正确性进展不构成盈利策略证明。

## 接入机制

`simulate_positions(..., daily_bars=True, research_dividends=book)` 接受已核验的普通USD税前分红账本。当前限定legacy日线执行，不与allocation模块、cost_aware或分拆附属资产账本混用，不默默忽略不支持的组合。legacy仍是共享现金、先卖后买、无杠杆账户。

- 除息日开盘交易前，按实际前收盘持仓确认应收。开盘及收盘权益都计入应收，因此机械除息不会凭空造成组合财富损失。
- 支付日在收盘后转现金，后续交易日才能使用；未支付应收始终不能参与买入资金检查。所有成交仍使用原始股价。
- 单股止损比较“当前股价＋当前持股对应的每股累计分红信用”与原始平均买入成本的止损线。新增股份按旧股比例稀释信用，部分卖出保留剩余股信用，全部卖出清零。会计成本基础不因普通分红改变。这是一项明确的研究止损约定，不声称复现券商规则。
- 每日和最终输出单列dividend_income、paid、receivable，逐股贡献加入已确认收入，且不将应收计作股票市场暴露。交易已实现损益、价格未实现损益仍单列：总权益变化=两者之和+已确认分红收入。
- 期末有未付应收时，不提供假装即时变现的清算收益；保留应收估值。事件在样本外、证券缺失、账本重复使用等均拒绝。

原价信号还没有做总回报调整；仅接入现金和风险不能声称所有策略输入已修复。未来取得的供应商信息是否当时可见也不由账本自动证明。

## 合成账户结果

两个股票各目标50%，零费用，从现金分批建仓。A从100机械除息至94、每股派6，B始终100。例子只用于验证会计，不能用它证明真实股票一定会精确下调股息金额。

除息前两股各500股，可用现金零。原始无分红账户损失3%并触发2%组合停机；接入账本后股票少3000、应收增加3000，总权益仍100000，不触发机械止损。支付前无法补买；支付日收盘3000转现金，下一日才买入31股A。新增股份使每股分红信用下降，总信用守恒。

另一个相同价格案例将支付日延至样本之后：期末3000仍为应收，可用现金仍零，未给出即时清算收益。全部逐日曲线、订单、信号、持仓、会计归因保存在dividend-engine-synthetic.json。

## 验证范围

新集成用例覆盖权益/贡献对账、止损、付款前不能花用、付款后再投资、信用稀释、跨终点应收，以及空账本和重复使用。账本已有用例与原position用例合计8项通过；随后增加跨终点断言并复查2项集成与1项分拆测试，3项全部通过（两轮合计覆盖9个不同用例）。

两个真实账户也已核验：新增12股最近一年固定组合、2022—2025连续固定组合，在传入空分红账本时，全部既有指标及逐股贡献与历史档案精确一致。它们分别包含未停机和已停机路径，记录见dividend-engine-checks.json。未将空账本一致性当作分红数据已可信。

复现针对性检查：`uv run --locked pytest -q tests/test_dividend_position.py tests/test_cash_dividend_book.py tests/test_position.py tests/test_position_distributions.py`。没有用新增策略收益测试替代会计测试。
