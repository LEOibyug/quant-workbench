# 本地美股策略平台范围与课件分析

日期：2026年9月17日。状态：需求收敛稿，未开始软件实现。

## 1 已明确的产品范围

- 全部本地原生部署，不以Docker、虚拟机、云或迁移为前提。
- 前后端分离；前端分为研究面板和使用／展示面板，可以是同一个Web应用的两个独立入口。
- 按用户最新说明，“系统隔离”指面板和操作流程分开，不要求容器、主机或安全沙箱隔离。界面分开不等于后台资源或权限隔离，本项目不对此作额外承诺。
- 支持按市场、股票或股票组、时间范围取得历史数据；数据供应商通过适配器扩展，不默认一次接入所有供应商。
- 支持策略编写、迭代、历史交易模拟、成本和绩效分析。
- 训练／开发与最终测试的数据划分继续保留。这是实验有效性要求，与两个前端面板是否分开是两回事。
- 市场暂定美股，目标为短期高频交易。交易时间尺度尚未明确，不直接将其解释为毫秒级专业高频。
- 保留真实账户实时交易扩展能力；尚未确定首版是否接真实券商。

建议定位为“本地美股日内策略研究与运行工作台”。首先按1分钟信号、数分钟至数十分钟持仓讨论，随后可扩展到秒级和逐笔。这个时间尺度是建议，仍需用户确认。普通本机和互联网券商接口可以用于日内自动交易，不能据此承诺毫秒／微秒级竞争优势。若目标是盘口抢单或做市，数据、队列、延迟与执行模型需要重新确定，但无需因此预设云或容器部署。

### 2.2 不能直接照搬的内容

- 课件主要例子来自A股日线或多日调仓，不能视为美股高频收益证据；“高频波动”在均线章节中是信号处理概念，并不代表高频交易架构。
- 第4讲7页的反复筛选和回测应只发生在开发／验证数据中；若持续查看最终测试并据此改策略，最终测试就已转化为开发数据。
- 第9讲45—49页的DTW示例涉及涨停和100股交易单位，需要替换为目标市场与券商规则。选择“当日涨幅最高股票”时，只能用决策时已经发生的涨幅，不能在盘中读取全日结果。
- 第3讲30页提出个人可不考虑流动性的说法，不适用于本项目的频繁交易。价差、可成交量、冲击成本对小账户同样重要。
- 第9讲59页关于深度学习预测更准确的描述不能作为本项目保证；必须与简单策略在同一测试区间和成本口径下比较。
- 课件的综合评分、用户画像和SEA收益算法不默认成为首版必需项。固定初始资金、无外部现金流时先按账户净值计算；以后支持入金出金再分别提供时间加权收益及资金加权收益。

### 3.1 “特征鲜明”如何量化

建议由系统对候选股票计算以下滚动特征，而不长期依赖人工贴标签：

- 过去20个完整交易日的成交金额和成交量、分时段相对成交量。
- 日内实现波动、开盘跳空、开盘区间振幅、趋势延续和反转幅度。
- 最佳买卖价差的中位数与高分位数、报价深度、可成交量；没有报价数据时标记为未知。
- 与市场、行业及其他候选股票的滚动相关性；相关不等于可交易的因果关系。
- 事件日与非事件日标签；事件必须使用当时可获知的时间戳。
- 相对于预期单笔交易金额的参与率和成本。

初期使用开发期数据制定筛选阈值，在测试期冻结规则。不按测试收益挑股票、窗口、阈值或费用模型。

已核实的两个数据源候选：

1. [Alpaca Market Data官方说明](https://docs.alpaca.markets/docs/about-market-data-api)：支持历史与实时数据、HTTP与WebSocket。个人Basic计划实时美股覆盖IEX，页面标注历史自2016年起、最近15分钟有访问限制；Algo Trader Plus页面标价99美元／月，实时覆盖全美股交易所。账号可用性、历史逐笔与报价权限及具体数据范围需以账户和端点验证。免费实时IEX不能当作全市场成交量或完整最优报价。
2. [Databento美股官方介绍](https://databento.com/equities)：提供历史及实时股票／ETF数据、逐笔、报价及按数据集提供的深度／逐订单数据；页面展示Nasdaq TotalView-ITCH等交易场所产品。若目标是秒级或盘口研究，优先按股票、日期、Schema和市场覆盖估算下载费用与存储，再选数据集。

建议先完成统一接口`list_symbols / fetch_bars / fetch_trades / fetch_quotes / corporate_actions / calendar`，首版接一个供应商并支持本地CSV／Parquet导入。接口需报告数据能力、来源、市场覆盖、时间粒度和缺口。选择供应商取决于预算和时间尺度；本次没有订阅、注册或下载付费数据。

技术建议为TypeScript Web前端、Python本地后端和计算引擎；SQLite保存小规模项目／任务元数据，Parquet保存行情，DuckDB用于本地分析查询。数据量、并发和个人技术偏好确认后再定具体版本与库。系统运行本地不等于数据获取离线；同步行情仍需互联网。大模型、用户画像、社区、机构权限、收费、云和高频专用基础设施不列入默认首版。

## 6 回测可信度与成本

### 6.1 数据与实验隔离

1. 按时间顺序划分训练、验证和最终测试，多个股票使用一致的时间边界，避免一只股票的未来行情通过另一只股票进入特征。
2. 标准化、缺失值填充参数、特征筛选、股票池阈值及模型参数都只能在允许的开发区间拟合。
3. 日内标签可能跨越分区边界，需要移除标签未来区间触及验证／测试的训练样本；隔离间隔根据实际标签与持仓跨度确定。
4. 指标预热可以读取测试开始前已经发生的历史数据，不计入测试收益；不能借预热拟合测试数据。
5. 记录代码、参数、数据快照、成本设置、随机种子、区间和模型。最终测试后改策略应创建新实验，已经看过的测试不能继续宣称完全未见。
6. 只向策略逐步提供决策时已知的数据。只分前端页面不能替代这套时间边界。

### 6.2 交易与成交

- 首版建议常规交易时段、只做多、不加杠杆、收盘前退出；均是待确认的范围建议。
- 交易日历使用America/New_York处理夏令时、节假日、半日市；存储使用统一UTC时间和明确的Bar结束时间。
- 信号在K线收盘后产生，订单只能在信号产生和模拟延迟之后的可交易事件成交。以当根收盘价无成本成交会高估表现。
- 使用报价时，买入从卖价侧、卖出从买价侧模拟，另计算冲击；不能再重复加一次完整价差。只有K线时采用显式价差／滑点假设，并将结果标为近似。
- 限价单不以“价格触及”直接认定全部成交；设置成交量限制、部分成交、到期和撤单。若一分钟内同时触发止损止盈而顺序不可知，使用明确保守规则或更细数据。
- 包含佣金及最低收费、适用的交易和监管费用、买卖价差、冲击、滑点；做空时另需借券和可借量，加杠杆时另需融资费用。费率按券商和生效日期配置，不使用A股印花税模板。
- 实盘前再核实目标券商账户的当期日内交易、结算与购买力规则，不将旧规则或阈值写死。

### 6.3 有效指标

净收益与净值、成本前后差异、最大回撤、按日收益计算并注明年化口径的Sharpe／Sortino、每日收益分布、交易次数、持仓时长、胜率与盈亏比、单笔净期望、换手、成交率、成本占比、分股票与分时段贡献。分钟收益直接乘简单年化系数可能忽视自相关，首版优先采用按日汇总口径。

同时展示SPY／QQQ市场背景和同股票买入持有对照；日内不隔夜策略与买入持有的风险暴露不同，需注明，不能把差值直接解释为纯策略能力。

策略模板建议先用双均线验证引擎，再研究开盘区间突破、日内VWAP偏离回归；后两者是针对本项目新增的研究假设，不是课件已验证结果。VWAP若仅由分钟线近似计算需标记，不能等同于真实逐笔成交量加权价格。SVM、DTW、遗传算法及深度学习留到数据和评估闭环成立后加入。

## 7 仍需用户回答的五组问题

1. **频率**：这里的短期高频，期望平均持仓是数分钟、数秒，还是小于一秒？首版建议1分钟信号、数分钟至数十分钟持仓。
2. **数据与范围**：历史分钟／逐笔数据预算大致多少，想覆盖多长时期？建议先取覆盖不同市场状态的12—24个月分钟数据，小范围再购买逐笔／报价样本。
3. **交易边界**：是否接受常规时段、只做多、不加杠杆、当日清仓的首版？如果需要盘前盘后、做空或隔夜，请指出。
4. **开发方式与设备**：策略用Python代码和参数模板是否合适？最终是否就在当前Mac上运行，内存及可用磁盘大概多少？
5. **首版运行目标**：使用面板先做历史回放，还是也要实时模拟？真实账户是仅保留接口，还是已有券商需要接入？可同时给模拟初始资金规模，用于成本和购买力模型。

先回答这五组即可。候选股票、基础指标、本地结构与课件方法的取舍已提供具体建议，无需再让用户重复决定全部参考功能。
